# AIOps 工程师能力地图

## 老师先解释这张地图怎么用

能力地图像课程导航：帮你找到前后依赖，不要求一次掌握所有格子。AIOps 是 Artificial Intelligence for IT Operations，意思是把数据分析和人工智能用于 IT 运维。它需要先有可用的数据、可靠的软件和可验证的操作流程。新同学先选一条“发现问题到恢复服务”的链，沿路补知识。

```text
Service（服务：用户真正使用的功能）
  -> Telemetry（遥测：指标、日志和链路证据）
  -> Detection（检测：发现偏离正常的表现）
  -> Diagnosis（诊断：依据证据解释可能原因）
  -> Response（响应：选择动作并控制影响）
  -> Verification（验证：检查用户功能是否恢复）
```

你先问自己：能否让一个程序运行？能否知道它是否健康？能否解释它为什么失败？能否验证修复？每个问题都对应一组能力，先补挡住当前问题的部分。

| 地图里的英文 | 中文解释 | 第一次学习要观察什么 |
|---|---|---|
| DNS / HTTP / TLS | 域名解析 / 网页请求协议 / 传输加密协议 | 名字怎样变成地址，请求怎样返回，证书为什么参与连接 |
| SLI / SLO / SLA | 服务指标 / 内部目标 / 对外约定 | 用什么分子分母计算，目标窗口是多少，谁承担约定 |
| Metrics / Logs / Traces | 指标 / 日志 / 链路 | 汇总趋势、具体事件、跨组件耗时分别在哪看 |
| Pod / Deployment / Service | 一组协作容器 / 管副本和更新的控制器 / 稳定访问入口 | 实例变化后请求怎样找到可用副本 |
| Ingress / HPA | HTTP 入口规则 / 水平自动扩缩容 | 外部请求怎样路由，副本数根据什么指标变化 |
| ConfigMap / Secret | 普通配置 / 敏感配置资源 | 谁可以读取，变更怎样生效；Secret 本身不等于自动加密 |
| LLM / RAG | 大语言模型 / 检索增强生成 | 模型答案引用什么资料，资料不全时如何处理 |
| MTTD / MTTR | 平均发现时间 / 平均恢复或修复时间 | 先明确每个起止时间和口径，再计算平均值 |

基础自测：给一位同学画出“浏览器—服务—数据库”，解释三条连接各自验证什么。进阶自测：移除一个服务副本，预测剩余容量，再用实验结果检验。面试自测：对方问“为什么不用另一个方案”时，能给出需求、证据和取舍，而非只说自己熟悉。

## 基础运维

- Linux：进程、文件系统、网络、systemd、性能分析。
- 网络：DNS、HTTP、TLS、负载均衡、常见故障定位。
- 数据库与中间件：MySQL、Redis、MQ 的基础监控和排障。
- 自动化：Shell、Python、Ansible 或其他运维编排工具。

## SRE 与可靠性

- SLI/SLO/SLA。
- 错误预算。
- 监控设计和告警治理。
- 事件响应和复盘。
- 容量评估和性能压测。

## 可观测性

- Metrics：Prometheus、PromQL、exporter。
- Logs：结构化日志、日志模板、错误聚合。
- Traces：OpenTelemetry、链路上下文、跨服务定位。
- Dashboards：Grafana、业务视图、值班视图。

## 云原生

- Docker：镜像、容器、网络、存储。
- Kubernetes：Pod、Deployment、Service、Ingress、ConfigMap、Secret、HPA。
- CI/CD：流水线、发布策略、回滚、灰度。
- 平台工程：把重复流程做成平台能力。

## 数据与 AI

- Python 数据处理：pandas、numpy、可视化。
- 异常检测：阈值、动态基线、IsolationForest。
- 事件关联：时间窗口、拓扑、相似日志、变更记录。
- LLM 应用：告警摘要、runbook 推荐、知识库检索。
- 评估：误报、漏报、MTTD、MTTR、人工节省时间。

## 求职表达

- 不是说“我学过 AIOps”，而是说“我用可观测数据做了一个能降低告警噪声的工具”。
- 不是说“我懂 AI”，而是说“我知道模型何时只能推荐，何时可以进入自动化流程”。
- 不是说“我年龄 37”，而是说“我有生产经验，知道自动化必须带审计、分级和回滚”。
