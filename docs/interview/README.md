# AIOps 面试准备

## 老师带你从“知道答案”走到“经得住追问”

先把目标放对：面试训练是在检验你能否解释和处理问题。完全零基础时，可以从本地实验说明学习能力；已有工作经验时，把真实案例里的证据和责任讲清楚。下面的自我介绍结构是可替换的写法，只有实际做过的事情才能填进去，不能把“我有多年经验”或“做过几个项目”直接当作自己的事实。

我们拿“页面突然变慢”练一轮。第一问，慢发生在哪里？你需要区分浏览器、入口、业务服务、数据库和外部依赖。第二问，你凭什么这样判断？给出同一时间窗口的延迟、错误、日志和请求标识。第三问，恢复动作是什么？解释为什么选择限流、扩容或回滚，并说明影响范围。第四问，怎样证明恢复？回到用户操作、错误比例和持续观察。

### 一道题怎样回答五层

1. 定义层：用三十秒说清用途。例：“指标看整体变化，日志看事件细节，链路看同一次请求经过哪些服务。”
2. 机制层：用三分钟画出数据怎么产生、如何关联、存到哪里、怎样查询。解释请求标识由谁生成，哪些日志可能没有关联字段。
3. 取舍层：说明代价。记录越细可能越耗资源，也可能带入敏感信息；采样减少成本，同时可能遗漏罕见问题。
4. 故障层：回答证据缺失怎么办。先确认采集进程、队列、时间与筛选条件，再判断业务是否真的没有事件。
5. 设计层：给定规模和恢复目标，选择容量、权限、冗余与回滚方案。明确哪些数字是题目假设，哪些是自己的实验测量。

### 老师给你的参考答案与下一问

问：“CPU 不高，为什么服务仍然慢？”参考答案：“CPU 是处理器工作量，服务可能在等数据库连接、锁、磁盘或网络。我会看请求耗时分布、线程等待和下游指标，再针对同一批慢请求验证。”继续追问：“线程数加倍一定有效吗？”答案应指出等待的资源可能并未增加，更多并发还可能压垮下游。

问：“用了 AI 就能自动定位根因吗？”参考答案：“模型可以整理线索并提出假设，结论仍要由时间线、依赖关系和可验证证据支持。缺少数据时，应说明未知并建议补采。”继续追问：“怎样评估？”讨论标注集、时间切分、误报、漏报、证据引用正确率和人工节省时间，不能只给一次演示。

问：“备份任务成功就代表能恢复吗？”参考答案：“任务成功证明执行过程满足其成功条件；恢复还要检查文件完整性、密钥、版本兼容、恢复顺序以及业务验收。”下一问是恢复用时和允许丢失多少数据。RTO 指恢复时间目标，RPO 指恢复点目标，分别约束时间和数据损失。

### 十五分钟模拟面试

前两分钟讲一个真实实验背景；三分钟画请求链；四分钟让对方追问两个机制；四分钟讨论一个故障和回滚；最后两分钟记录答不上来的问题。评分用“是否可解释、是否可复现、是否有证据、是否能说明边界”四项，每项记 0、1、2 分。分数用于找缺口，不是预测录用概率。

用手机录音后自查三处：有没有只报产品名字，有没有把可能原因说成确定根因，有没有结果却没有验收方法。把最弱的一题写进下一次实验计划，再回对应技术栈文章练习。

## 自我介绍结构

1. 当前背景：填写自己的实际工作或学习经历，以及能用证据说明的能力。
2. 学习方向：说明怎样把可观测数据、规则或模型用于发现与处理故障；解释 MTTD（平均发现时间）、MTTR（按约定口径计算的平均恢复时间）。
3. 已完成项目：只填真实完成的项目，给出运行方式、输入输出和局限；计划中的项目单独说明。
4. 工程判断：用自己做过的权限、审计、验证或回滚练习说明风险意识。

## 必备问题

- AIOps 和传统监控有什么区别？
- 指标、日志、链路追踪分别解决什么问题？
- Prometheus 的 pull 模型有什么优缺点？
- 什么是 SLI/SLO？如何设计一个服务的 SLO？
- 为什么告警不能只按 CPU 阈值配置？
- 如何降低告警误报？
- 如何判断一个异常检测模型是否有价值？
- IsolationForest 适合什么场景？不适合什么场景？
- 你如何把 runbook 自动化？风险如何控制？
- 出现模型误判导致错误动作怎么办？
- Kubernetes 里的 Deployment、Service、Ingress、HPA 分别做什么？
- 一次生产故障你会如何复盘？

## 8 个工程故事

- 最复杂的一次故障定位。
- 最有价值的一次自动化。
- 一次监控告警改造。
- 一次性能或容量问题。
- 一次发布或变更事故。
- 一次跨团队协作。
- 一次误报/漏报治理。
- 一个你做过或准备做的 AIOps 项目。

## 回答原则

- 先讲场景，再讲动作，最后讲结果。
- 多说数据：告警数量、处理时间、误报率、故障影响、自动化节省时间。
- 不把 AI 说成万能；要讲边界、评估、审计、回滚。
- 年龄不是重点，生产经验和风险意识才是重点。
